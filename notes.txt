Every lab so far has started from patient data already sitting in your code: a list, a dictionary, typed in by hand. Real health records don't work that way, they come from a file someone else created, and that file is never as clean as a hand-typed example. This lab reads patient data from a provided CSV file instead of hard-coding it, and writes your results back out to a new file instead of just printing them.

patient_records.csv Download patient_records.csv is provided with this assignment. Open it in a text editor before you start writing code, you'll see exactly what you're dealing with: extra spaces around some values, and some patients with no condition recorded at all (an empty field, not a missing one this time, since every row in a CSV has the same number of columns). Your code has to clean that up, not assume it's already clean.

What Your Program Must Do

    Write a function load_patients(filename) that opens patient_records.csv, reads it, and returns a list of patient dictionaries with these keys: patient_id, name, age, weight_lbs, height_in, condition. Skip the header row. age, weight_lbs, and height_in must be stored as int, not as text, you'll need to convert them.
    Every field in this file may have extra leading or trailing spaces. Strip every field after splitting the line, not just the ones that look messy when you print them, several that look fine actually aren't.
    Write (or reuse from Lab 6/7) a calculate_bmi(weight_lbs, height_in) function.
    For each patient, build a summary line with: name (properly capitalized), age, BMI (1 decimal place), and condition. A patient with an empty condition field displays "Not specified". A patient whose condition is literally the text "none" displays "None", that's a real recorded value, not a missing one, same distinction Lab 7 made with .get().
    Calculate the average BMI across all patients, and identify the patient with the highest BMI and the patient with the lowest.
    Write all of this to a new file named patient_summary.txt: one summary line per patient, a blank line, then four summary lines for patients processed, average BMI, highest BMI, and lowest BMI. See Expected Output Shape below for the exact wording.
    After writing the file, print one confirmation line to the console: Wrote summary for N patients to patient_summary.txt, with the real count in place of N.

Requirements

    Use a with open(...) block to read the CSV and another to write the summary file. Don't open a file without with and forget to close it.
    load_patients() must be a real function with a docstring, returning the list rather than printing from inside it.
    Strip every field, not just the ones you can see are messy. Some values in this file have spaces that don't show up unless you look closely.
    Your BMI numbers for P001 through P005 must match Lab 6 and Lab 7's for the same patients. If they don't, you have a bug.

Watch Out For

    int("210") works, int(" 210") also works since int() ignores surrounding whitespace, but int("") crashes. An empty numeric field isn't a problem in this dataset, but know the difference between a numeric field and a text field here, you strip text fields for a different reason (so .title() and comparisons behave), not to make int() happy.
    A blank line at the very end of a file is common, most text editors add one. Check if not line.strip(): continue before trying to split it, or you'll get an IndexError trying to pull a field out of nothing.
    condition.title() on an empty string returns an empty string, not "Not specified". You still need the explicit check, .title() doesn't do that work for you.
    Opening a file for writing ("w") erases it if it already exists. Run your program as many times as you want while testing, each run should produce the same correct file, not append to the last one.
